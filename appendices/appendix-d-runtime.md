# 附录 D　运行时 ABI

[中文目录](../README.md) · [英文原章](https://sdiehl.github.io/write-you-a-haskell/appendix-d-runtime.html) · [配套源码](https://github.com/sdiehl/write-you-a-haskell/tree/51c70f804173c9d013187c543a353686b413ad50/crates/ch24_gc/rt/src)

假设编译器把一个闭包交给运行时。运行时怎么知道去哪里取代码地址、哪些位置存着捕获的变量？这些细节由双方事先约好，这套二进制层面的约定就是 **ABI**。这里记录的是本书最终版原生编译器与 `fun-rt-24` 之间的约定。支持的平台是 Apple Silicon 上的 macOS，以及 x86-64 或 AArch64 上的 Linux。它们的机器字和指针都是 64 位。这份 ABI 供这一版编译器内部使用，Fun 没有向用户开放自己编写外部函数接口（FFI）的机制。

## 机器字与对象布局

每当一个 Fun 值作为实参传进去，或作为结果返回，它都占一个机器字。在 LLVM 一侧是 `i64`，在 Rust 一侧是 `u64`。先看最低位。最低位为 1，值就直接装在这个字里，称为**立即值**。最低位为 0，通常就把整字当作对齐的对象地址。初始化时临时填入的全零占位符是个例外。

| Fun 值 | 一个机器字里放什么 |
| --- | --- |
| `Int` | `(n << 1) \| 1`。给最低位留出标记后，用其余 63 位存有符号补码整数 |
| `Char` | 把 Unicode 标量值左移一位，再把最低位置 1 |
| 零元构造器（没有字段） | `(tag << 1) \| 1`，其中 `tag` 是该构造器的编号 |
| 堆上的值 | 对象头的地址，按 8 字节对齐 |

只看位模式，分不出完整的源语言类型。比如 `False`、`[]`、`Nothing` 和 `()` 的机器字都可以是 `1`。对布尔值分支时，这个字代表 `False`。对列表做模式匹配时，它代表空列表。该用哪种解释，编译器从程序的类型就已经知道了。

对象从一个 64 位的**对象头**开始，紧跟着的是载荷的第 0 个字、第 1 个字，依此类推。把对象头从高位往低位拆开来看。

| 位编号（含两端） | 位宽 | 含义 |
| --- | ---: | --- |
| 63～32 | 32 位 | 载荷大小，只数对象头后面的机器字 |
| 31～8 | 24 位 | 构造器标签 `tag` |
| 7～0 | 8 位 | 对象种类 `kind` |

构造器按声明顺序编号，每个数据类型都从头编起。Prelude 里几组常用构造器的编号固定如下。

| 类型 | 构造器及其编号 |
| --- | --- |
| 布尔值 | `False=0`、`True=1` |
| 列表 | `[]=0`、`(:)=1` |
| `Maybe` | `Nothing=0`、`Just=1` |
| 单位类型 | `()=0` |
| 比较结果 | `LT=0`、`EQ=1`、`GT=2` |

同样是载荷里的一个字，它可能装着 Fun 值，也可能只是代码地址、计数或浮点数的原始位。回收器按对象种类决定该去哪些槽里找引用。

| 对象种类 | ID | 载荷从前往后放什么 | 回收时追踪什么 |
| --- | ---: | --- | --- |
| `CON` | 0 | 构造器的各个字段 | 所有字段 |
| `CLOSURE` | 1 | 慢入口的代码地址、形参个数（原始机器字）、捕获的值 | 捕获的值 |
| `PAP` | 2 | 闭包值、已给实参的个数（原始机器字）、这些实参 | 闭包和实参 |
| `DOUBLE` | 3 | binary64 浮点数的原始位 | 无 |
| `STRING` | 4 | 原始字节数，随后是 UTF-8 字节，末尾补齐到整个机器字 | 无 |
| `FORWARD` | 5 | 对象被搬到的新地址 | 仅供回收器识别的转发标记 |

零元构造器直接编码在机器字里，无需分配堆对象。所以每个能搬动的对象至少有一个载荷字，搬走后可以在原处留下新地址。另一个容易混淆的是字符串的两种长度。比如 `"猫"` 在堆上记为 3 个 UTF-8 字节，求长度的字符串原语却返回 1，因为它数的是 Unicode 标量值。[第 20 章 · 数据表示与运行时](../part-3/ch20-runtime.md)

## 函数入口与调用

若编译器已经知道被调函数，就能直接生成与它形参数量相符的调用。若手里只有一个闭包值，运行时还要判断实参究竟够不够。下面的 `tailcc` 是 LLVM 的尾调用约定。其余标为 C 的入口遵循 C 调用约定，签名里的 `u64`、`usize` 等写法沿用本书。

| 入口 | 调用约定与签名 |
| --- | --- |
| 目标已知的函数 | LLVM · `tailcc i64 f(i64 env, i64 a1, ..., i64 an)` |
| 慢入口适配器 | C · `u64 slow(u64 closure, const u64 *args)` |
| 通用调用入口 | C · `u64 rt_apply(u64 closure, usize n, const u64 *args)` |
| 少量实参的专用入口 | C · `u64 rt_applyN(u64 closure, u64 a1, ..., u64 aN)`，`N` 从 1 到 4 |
| 创建部分应用对象（PAP） | C · `u64 rt_make_pap(u64 closure, usize n, const u64 *args)` |
| 回填递归闭包的捕获槽 | C · `void rt_closure_set(u64 closure, usize index, u64 value)` |

慢入口收到的实参数必须刚好等于函数定义写出的形参数。凑齐的工作由 `rt_apply` 负责。遇到 PAP，它把先前存好的实参与这次给的实参接成一列。实参仍然不足，就把已经给出的留在 PAP 里。刚好够，就调用目标。还有多余的，就先拿够数的那一段调用目标，再把剩下的传给返回的函数。只有目标已知、又处在尾位置的调用，才保证生成原生尾跳转。跨越 C 与 `tailcc` 的调用边界时，适配器的栈帧仍要保留。

Fun 严格求值，发起调用时，所有实参都已算出。传给运行时的原始实参数组在整个调用期间都必须可读。数组的位置可以不变，它里面的某个字指向的对象却可能被回收器搬走。因此，若要长期保留这个缓冲区，就要交给负责登记根的对象来管理。慢入口会先读出实参，建立编译器为它生成的根栈帧，然后才允许发生内存分配。

## 分配内存与登记根

**根**是回收器寻找活对象的起点。对会搬动对象的回收器来说，登记根时要交出能改写的槽位。这样，对象搬走后，回收器才有地方把旧地址换成新地址。

| 导出函数 | 调用约定的含义 |
| --- | --- |
| `void rt_init()` | 使用 Boehm 时，初始化回收器，并向它登记调用运行时的当前线程 |
| `u64 *rt_alloc(usize words)` | 分配可供回收器扫描的存储，按机器字计数，含对象头 |
| `u8 *rt_alloc_atomic(usize bytes)` | 分配不含指针的存储，按字节计数 |
| `void rt_use_copying()` | 在初始化之前选用单线程的移动式复制堆 |
| `void rt_roots_push(u64 *slots, usize n)` | 登记生成代码提供的一段根槽。槽位须已初始化，而且可写 |
| `void rt_roots_pop()` | 撤销当前这段根槽的登记 |
| `void rt_global_root(u64 *slot)` | 把静态全局槽登记为根，登记持续到进程结束 |

一次内存分配可能在返回前就触发回收。分配一旦成功，调用者要先填好新对象的全部内容，才能再次分配。原生程序启动时也有先后顺序。先登记全局槽，再把函数放进去，或对全局值求值。静态字符串对象不可修改，地址也固定。使用 Boehm 的后端还会保留一张静态字符串地址表。

在 Rust 这一侧，`Roots` 和 `GlobalRoot` 持有地址稳定的缓冲区，从登记起一直管到自身被 `drop`，移动式回收器会就地更新其中的槽。比如先从根槽读出地址 `p`，然后分配一个新对象。这次分配若把 `p` 指向的对象搬走，根槽里会换成新地址，手里抄下来的 `p` 却还是旧的。借来的字符串切片也有同样的问题。所以，未受根保护的指针副本和借用的字符串切片都不能跨越一次分配继续使用。字符串原语会先把输入解码成自己拥有的 Rust 值，然后才给结果分配空间。[第 24 章 · 精确垃圾回收](../part-3/ch24-garbage-collection.md)

## 原语、报错与退出

每个名为 `prim_*` 的操作都有对应的 C 导出符号 `rt_prim_*`。每个实参各占一个机器字，有返回值时结果也占一个字，连单位值 `()` 都要照样传回。整数和 `Double` 的算术有时会由编译器直接生成指令。较复杂的操作则与解释器共用同一份安全 Rust 实现。

表中省略了共同的前缀。例如，`intAdd/Sub` 代表 `intAdd` 和 `intSub`，对应的导出符号分别是 `rt_prim_intAdd` 和 `rt_prim_intSub`。

| 原语 | 实参 | 结果 |
| --- | --- | --- |
| `intAdd/Sub/Mul/Quot/Rem/Div/Mod` | 两个 `Int` 字 | `Int` 字 |
| `intNeg` | `Int` | `Int` |
| `intEq/Lt/Le` | 两个 `Int` 字 | `Bool` 立即值 |
| `dblAdd/Sub/Mul/Div/Pow` | 两个装箱的 `Double` | 装箱的 `Double` |
| `dblNeg/Sqrt/Exp/Log/Sin/Cos` | 一个装箱的 `Double` | 装箱的 `Double` |
| `dblEq/Lt/Le` | 两个装箱的 `Double` | `Bool` 立即值 |
| `intToDbl`、`dblFloor/Round/Truncate` | 前者接收 `Int`，后三者接收 `Double` | 前者返回 `Double`，后三者返回 `Int` |
| `chrOrd`、`chrChr`、`chrEq/Lt` | 分别接收一个字符、一个整数、两个字符 | 分别返回 `Int`、`Char`、`Bool` |
| `strAppend/Length/Eq/Compare` | `strLength` 接收一个字符串，其余接收两个 | 依次为 `String`、`Int`、`Bool`、`Int` |
| `strUnpack`、`strPack` | 分别接收一个字符串、一个字符列表 | 分别返回字符列表、字符串 |
| `showInt/Double/Char/String` | 一个对应类型的值 | `String` |
| `readInt` | `String` | `Maybe Int` |
| `putStr`、`getLine` | 分别接收字符串、单位值 | 分别返回单位值、字符串 |
| `trace` | 一条字符串消息和一个任意类型的值 | 原样返回第二个实参 |
| `error`、`exit` | 分别接收字符串、`Int` | 两者都不会返回 |

整数运算结果按 $2^{63}$ 取模回绕。浮点数转 `Int` 用的却是饱和转换，超出范围就取最近的 `Int` 边界值，NaN 转成 0。整数除法或取余时除数为零、整数转字符时遇到无效码点、`getLine` 读到输入结束，以及模式匹配失败，都会触发运行时错误。这里的除零特指整数运算，`Double` 除法遵循浮点规则。[原语实现](https://github.com/sdiehl/write-you-a-haskell/blob/51c70f804173c9d013187c543a353686b413ad50/crates/ch24_gc/rt/src/primitives.rs)

| 导出函数 | 行为 |
| --- | --- |
| `rt_error(u64 string)` | 刷新标准输出，向标准错误写出 `fun: MESSAGE`，以状态码 1 退出 |
| `rt_pattern_fail(const char *file, u32 line, u32 col)` | 报出匹配失败的源文件、行号和列号，以状态码 1 退出 |
| `rt_div_zero()` | 报出 `fun: divide by zero`，以状态码 1 退出 |
| `rt_exit(i32 code)` | 刷新标准输出，按给定状态码终止进程 |

程序真正的入口是编译器生成的 C `main`。它先初始化运行时，再按依赖顺序对全局绑定求值，然后把代表单位值的机器字 `1` 传给 Fun 源码里的 `main`。正常执行到末尾就成功退出。如果运行时本身触发 Rust `panic`，进程会直接中止，避免异常沿着生成的代码展开调用栈。
