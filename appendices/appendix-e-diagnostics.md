# 附录 E　诊断代码速查

[中文目录](../README.md) · [英文原章](https://sdiehl.github.io/write-you-a-haskell/appendix-e-diagnostics.html) · [编译器诊断代码表](https://github.com/sdiehl/write-you-a-haskell/blob/51c70f804173c9d013187c543a353686b413ad50/crates/ch24_gc/src/diagnostics/codes.rs)

看到 `E0245`，先看报错下方标出的那段源码。主标注指出「哪里触发了这条诊断」，消息和次要标注补充「在这段程序里，为什么会出问题」。同一个问题出现在不同程序里，文字可能不同，编号仍然一样。这份索引来自 Fun 最终版编译器的诊断代码表。

| 代码 | 编译器在说什么 |
| --- | --- |
| `E0001` | 词法分析器认不出这里的记号。 |
| `E0002` | 记号本身认得，但放在这里不符合语法。 |
| `E0003` | 缩进或分块不符合布局规则。 |
| `E0004` | 读取记录字段的点号用法不合法。 |
| `E0101` | 在当前作用域里找不到这个变量的定义。 |
| `E0102` | 同一个名字重复定义了。 |
| `E0103` | 找不到这里引用的构造器或类型。 |
| `E0104` | 声明记录类型时，同一个字段名出现了两次。 |
| `E0110` | 试图重新定义保留的运算符。 |
| `E0111` | 在 Prelude 以外的代码中使用了仅供 Prelude 使用的原语。 |
| `E0120` | 递归绑定中出现了普通值。Fun 要求这组绑定的右侧在脱糖后都是函数。 |
| `E0130` | 给运算符声明了优先级和结合性，却找不到与这条声明对应的定义。 |
| `E0201` | 这里需要的类型与实际得到的类型不一致。 |
| `E0202` | 推断会得到一个无限类型，例如要让 `a` 等于 `a -> b`，代进去永远也写不完。 |
| `E0203` | 类型签名承诺得太多，函数体只能在更具体的类型下成立。 |
| `E0210` | 找不到满足这个类型类约束的实例。 |
| `E0211` | 实例里的方法定义不符合要求，或者同一个实例被重复声明。 |
| `E0230` | 类型有歧义。现有信息不足以决定该选哪个类型。 |
| `E0240` | 记录类型必须恰好有一个构造器。 |
| `E0241` | 构造记录时漏填了字段。 |
| `E0242` | 同一次字段绑定中，同一个字段被写了两次。 |
| `E0243` | 找不到这个字段名。 |
| `E0244` | 已经知道接收者是什么类型，但它没有声明这个字段。 |
| `E0245` | 取字段时有歧义，现有类型信息不足以判断要读哪种记录的字段。 |
| `E0250` | 程序入口 `main` 的类型必须是 `IO ()`。 |
| `E0301` | 种类（kind）不匹配。例如某处需要一个完整的类型，传来的却是还缺参数的类型构造器。 |
| `E0302` | 类型同义词只给了一部分参数，无法展开。 |
| `E0303` | 类型同义词的定义绕回了自身，形成循环。 |
| `W0001` | 模式匹配有遗漏，某些输入可能没有分支可走。 |
| `W0002` | 某一行匹配分支永远走不到。 |

编号的开头能帮你找到出问题的编译阶段。`E00xx` 来自词法分析、缩进布局或语法分析，`E01xx` 来自名称解析，`E02xx` 来自类型检查，`E03xx` 来自种类检查。一个阶段可能一次报出好几个问题。一旦遇到错误，编译器就停在这个阶段。

**两个容易查混的警告。** 比如给 `Maybe` 写模式匹配，只有 `Just x` 一行，就可能收到 `W0001`。编译器能举出反例时，还会给出像 `Nothing` 这样被漏掉的模式。如果第一行已经用 `_` 接住一切，后面再写一行 `Just x`，后面这行会收到 `W0002`。警告本身不会阻止编译。程序运行时真的遇上漏掉的输入，才会触发匹配失败的运行时错误。[第 16 章　编译模式匹配](../part-2/ch16-pattern-compilation.md)

**遇到歧义时该补什么。** 如果 `p.x` 报 `E0245`，而 `Point` 和别的记录都有字段 `x`，就给接收者 `p` 标明类型，例如写成 `(p :: Point).x`。如果有歧义的是类型类约束，可以让受约束的类型出现在结果类型中，或用类型标注明确选定它。Fun 不会替尚未解出的数值约束自动挑一个默认类型。[附录 B　类型规则](appendix-b-typing.md)

程序运行后才出现的错误会输出以 `fun:` 开头的消息，并以状态码 1 退出。`exitWith` 则使用程序指定的状态码。编译器的中间表示转储（dump）和内部一致性检查（lint）供开发编译器时调试使用。要按编号处理面向 Fun 源程序的诊断，请以上表为准。
